# Seoul Trip Planner

เว็บวางแผนเที่ยวโซล (ภาษาไทย) ใช้ได้ทั้งมือถือและคอม
เลือกวันเวลา → ดูสถานที่บนแผนที่ → หยิบสถานที่/ร้านใส่แผน → เทียบการเดินทาง → ดูผลต่อเวลาทั้งวัน → ตรวจอากาศ/เสื้อผ้า → เปิดบนมือถือระหว่างเที่ยว

เป็น Static site (Vite + TypeScript) ไม่มี backend · ข้อกำหนดย่อดูที่ [SPEC.md](SPEC.md)

## เริ่มใช้งาน

```bash
npm install
cp .env.example .env.local   # ไม่บังคับ: ใส่ Google Maps API Key
npm run dev                  # http://localhost:5173
npm test                     # unit tests (Vitest)
npm run build                # ได้ไฟล์ static ใน dist/
npm run test:e2e             # ทดสอบบนเบราว์เซอร์ (ต้อง build ก่อน, ใช้ Google Chrome ในเครื่อง)
```

ไม่มี API Key ก็ใช้งานได้: จัดแผน กรอกเวลาเดินทางเอง ดูอากาศ และแชร์แผนได้ครบ ส่วนที่ใช้ไม่ได้มีเฉพาะแผนที่ Google และเส้นทางจากบริการ

## Google Maps และบริการเส้นทาง

1. ไปที่ Google Cloud Console → สร้างโปรเจกต์ → **ผูก Billing account** (Maps Platform ต้องมี Billing แม้ใช้ไม่เกินโควตาฟรี)
2. เปิด API สองตัว: **Maps JavaScript API** และ **Routes API**
   - แอปใช้ `Route.computeRoutes` ของ Routes library ใน Maps JS
   - ไม่ใช้ DirectionsService เพราะเป็น Legacy ตั้งแต่ 2025-03-01
3. สร้าง API Key แล้ว**จำกัดคีย์**:
   - Application restriction: *Websites (HTTP referrers)* เช่น `https://<user>.github.io/*` และ `http://localhost:5173/*`
   - API restriction: เฉพาะ Maps JavaScript API + Routes API
   - ตั้ง quota และ budget alert ใน Billing
4. (แนะนำ) สร้าง **Map ID** ใน Map Management สำหรับหมุดแบบ Advanced Marker ระหว่างพัฒนาใช้ `DEMO_MAP_ID` ได้
5. ใส่คีย์ได้ 2 ทาง:
   - ตั้ง `VITE_GOOGLE_MAPS_API_KEY` ตอน build
   - **หรือ** กดปุ่ม ⚙️ ในหน้าเว็บ (คีย์เก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่ติดไปกับลิงก์แชร์หรือไฟล์ JSON)

> เว็บ static ทุกเว็บเปิดเผยคีย์ให้เบราว์เซอร์เห็นเสมอ ความปลอดภัยจึงมาจากการจำกัด referrer, API และ quota ไม่ใช่การซ่อนคีย์

**ข้อจำกัดในเกาหลีใต้** (ตามหน้า https://developers.google.com/maps/coverage):
- **เดิน / ขับรถ / จักรยาน:** Google ระบุว่าไม่มีข้อมูลหรือคุณภาพต่ำ แอปจึงแสดง "บริการไม่รองรับ" แล้วให้กรอกเวลาเองหรือเปิด KakaoMap
- **ขนส่งสาธารณะ:** ขอเส้นทางทีละช่วง ใช้วันที่และเวลาออกจริงตามเวลาเกาหลี (Asia/Seoul) ขอได้ตั้งแต่ 7 วันย้อนหลังถึง 100 วันล่วงหน้า
- **ค่าโดยสาร:** แสดงเฉพาะเมื่อบริการส่งข้อมูลมา
- **ทางออกสถานี:** บริการไม่ได้ระบุหมายเลข แอปจึงแสดงว่า "ไม่ทราบ"

## อากาศ (Open-Meteo)

- ไม่ต้องใช้คีย์
- ขอข้อมูลด้วย `timezone=Asia/Seoul`
- พยากรณ์ล่วงหน้าได้ 16 วัน
- แคชข้อมูล 1 ชั่วโมง และมีปุ่มรีเฟรช
- แสดง attribution "Weather data by Open-Meteo.com" (CC BY 4.0) ตามเงื่อนไขแล้ว

เงื่อนไขการใช้งาน: ฟรีเฉพาะการใช้งาน**ไม่เชิงพาณิชย์** (ไม่เกิน 10,000 คำขอต่อวัน) ถ้าเว็บมีโฆษณาหรือขายสินค้า ต้องใช้แผนเสียเงินของ Open-Meteo

## เผยแพร่ผ่าน HTTPS (static hosting)

รัน `npm run build` แล้วอัปโหลดโฟลเดอร์ `dist/` (ตั้งค่า `base: './'` ไว้แล้ว จึงวางใน path ย่อยได้)

- **GitHub Pages (ฟรี):**
  1. ตั้ง remote `origin` เป็น repo บน GitHub (repo สาธารณะจึงใช้ Pages ฟรีได้)
  2. รัน `npm run deploy` ระบบจะรัน test, build แล้ว push `dist/` ขึ้น branch `gh-pages`
  3. ครั้งแรกให้ไปที่ Settings → Pages → Source: *Deploy from a branch* → `gh-pages` / `(root)`
  4. ถ้าต้องการใช้คีย์ Google ให้ใส่ `VITE_GOOGLE_MAPS_API_KEY` ใน `.env.local` ก่อน deploy หรือใส่ภายหลังผ่านปุ่ม ⚙️ ในหน้าเว็บ
- **Netlify / Cloudflare Pages / Vercel:** ตั้ง build command เป็น `npm run build`, output เป็น `dist` และตั้ง env `VITE_GOOGLE_MAPS_API_KEY`
- เพิ่มโดเมนที่ได้ (เช่น `https://<user>.github.io/*`) ใน HTTP referrer ของคีย์

มือถือและคอมเปิด URL HTTPS เดียวกันได้ ส่วนลิงก์ `localhost` มือถือเครื่องอื่นจะเปิดไม่ได้

## การบันทึกและส่งแผนข้ามอุปกรณ์

- **บันทึกอัตโนมัติ:** เก็บใน localStorage **ของเบราว์เซอร์เครื่องนั้นเท่านั้น** ไม่ซิงก์ข้ามเครื่องเอง ถ้าบันทึกไม่ได้ (เช่น โหมดส่วนตัว) แอปจะเตือนให้ Export JSON
- **เมนู 📤 แชร์/บันทึก:** คัดลอกลิงก์ / QR Code / คัดลอกเป็นข้อความ / Export–Import JSON
- **ลิงก์แชร์:**
  - แผนถูกบีบอัดไว้ในส่วน `#plan=…` ของลิงก์ ไม่ถูกส่งถึงเซิร์ฟเวอร์
  - เป็น**สำเนา ณ เวลาที่แชร์** ไม่ใช่การซิงก์สด
  - ตรวจข้อมูลก่อนนำเข้าทุกครั้ง และไม่รวม API Key หรือผลจากบริการ
  - ถ้ายาวเกิน 4,000 ตัวอักษร ให้ใช้ไฟล์ JSON แทน
  - ถ้าเครื่องปลายทางมีแผนเดิม จะให้เลือก "เปิดเป็นสำเนา" หรือ "แทนที่"
- **ข้อมูลในโค้ด:** `src/data` มีเฉพาะสถานที่สาธารณะ ไม่มีแผนส่วนตัวของใครฝังอยู่
- **ออฟไลน์:** service worker แคชไฟล์แอปไว้ (ทำงานเมื่อเปิดผ่าน HTTPS) จึงดูแผนที่บันทึกไว้ได้ พร้อมแจ้งว่าแผนที่ เส้นทาง และอากาศยังอัปเดตไม่ได้

## โครงสร้างโค้ด

| โฟลเดอร์ | หน้าที่ |
|---|---|
| `src/core` | คำนวณล้วน: `schedule.ts` ตารางเวลา · `compare.ts` แทรกจุด/แนะนำลำดับ · `weather.ts` จับคู่วันเวลาโซล · `clothing.ts` กฎการแต่งตัว · `time.ts` |
| `src/data` | `basePlaces.ts` พิกัดตั้งต้น · `places.json` ผลค้นคว้าพร้อมแหล่งข้อมูล · `templates.ts` แม่แบบ A/B/C |
| `src/services` | ตัวโหลด Google · `routes.ts` (คิว แคช กันผลเก่าทับผลใหม่) · `map.ts` · `weather.ts` |
| `src/storage` | localStorage · ลิงก์แชร์ · ตรวจข้อมูลก่อนนำเข้า |
| `src/ui` | หน้าจอ: คลังสถานที่ แผนรายวัน วันนี้ modal · `mapSpecs.ts` แปลงแผนเป็นหมุด |

แก้หรือเพิ่มสถานที่ที่ `src/data/places.json`:
- ใส่ `sources` และ `checkedAt` ทุกครั้ง
- ถ้าตรวจพิกัดไม่ได้ ให้ใส่ `lat`/`lng` เป็น `null` และ `coordStatus: "unverified"` (แอปจะไม่ปักหมุด)

## ผลการทดสอบ (รันจริง 13 พ.ย. 2026)

**`npm test` — ผ่าน 42/42 (Vitest)** ครอบคลุม:
- **ตารางเวลา:**
  - เปลี่ยนเวลาเริ่ม เวลาแวะ หรือวิธีเดินทาง แล้วช่วงที่เหลือคำนวณใหม่
  - ลบ/ย้ายจุดแล้วช่วงเดินทางเชื่อมกันถูกต้อง
  - เวลานัดที่ล็อกไม่ถูกเลื่อน: ถึงก่อนแสดงเวลารอ ถึงช้าแสดงเวลาที่สาย
  - ข้อมูลเดินทางที่ขาดไม่ถูกนับเป็น 0 นาที และไม่สรุปว่ากลับทัน
  - คำนวณถึงจุดสิ้นสุดที่ผู้ใช้เลือกเสมอ
  - เวลาเผื่อแยกจากเวลาที่บริการคำนวณ
- **เปรียบเทียบและลำดับ:**
  - แทรกจุดแล้วแสดงผลก่อนยืนยัน โดยแผนเดิมไม่เปลี่ยน
  - "แนะนำลำดับ" ไม่ย้ายจุดที่ล็อกเวลา
- **หมุดแผนที่:** ตรงกับวันและลำดับในรายการ สถานที่เดียวกันหลายวันรวมเป็นหมุดเดียว
- **อากาศ:**
  - จับคู่ชั่วโมงตามเวลาเกาหลี รวมช่วงที่ข้ามเที่ยงคืน
  - วันนอกช่วงพยากรณ์และค่า null ไม่ถูกสร้างเป็นตัวเลข
  - ใช้แคช ไม่เรียก API ซ้ำ
- **แต่งตัว:** อิงอากาศช่วงเย็นที่ออกเที่ยวจริง และไม่อนุมานหิมะจากอุณหภูมิอย่างเดียว
- **แชร์:** ลิงก์ส่งไปและอ่านกลับได้ครบ ตรวจข้อมูลก่อนนำเข้า และไม่มีคีย์ติดไป
- **เส้นทาง:** แปลงผลจาก Routes library เป็นขั้นตอนการเดินทางที่อ่านง่าย

**`npm run test:e2e` — ผ่าน 14/14 (Playwright + Chrome)**
- ทดสอบสองขนาดจอ: มือถือ Pixel 7 และเดสก์ท็อป 1440px
- ตั้งเขตเวลาเครื่องเป็น New York เพื่อยืนยันว่าแอปใช้เวลาโซล ไม่ใช่เวลาเครื่อง

ครอบคลุม:
- ไม่มี API Key แล้วส่วนจัดแผนยังใช้ได้
- เพิ่มสถานที่ผ่านหน้าเปรียบเทียบ และกดยกเลิกแล้วแผนไม่เปลี่ยน
- กรอกเวลาเดินทางเอง
- อากาศช่วงเย็น และข้อความเมื่อวันอยู่นอกช่วงพยากรณ์
- ไม่เรียก API อากาศซ้ำ
- บันทึก โหลดกลับ ส่งลิงก์ข้ามเครื่อง และเปิดเป็นสำเนา
- ไม่มีเนื้อหาล้นแนวนอน และปุ่มหลักสูงอย่างน้อย 44px
- แม่แบบต้องยืนยันก่อนแทนที่แผน
- ย้ายและลบจุดด้วยปุ่ม ไม่ต้องลากวาง

**ยังไม่ได้ทดสอบ (ต้องมีคีย์หรือสิทธิ์เพิ่ม):**
- การเรียก Google Routes จริง (ทดสอบเฉพาะโค้ดแปลงผลด้วยข้อมูลจำลองตามรูปแบบในเอกสาร)
- หมุดและเส้นทางบนแผนที่ Google จริง
- การเผยแพร่บน HTTPS และการเปิดจากมือถือภายนอก
- ข้อมูลอากาศจริงในชุด e2e (แอปเรียก Open-Meteo จริงได้ แต่ชุดทดสอบใช้ข้อมูลจำลองเพื่อให้ผลคงที่)
